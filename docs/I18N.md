# I18N.md — English + Romanian UI

Goal: every app switchable between RO and EN, with the choice shared
across all three pages.

## The existing pattern (`index.html`)

Four moving parts — read `index.html:392-480` and `588-599`:

```js
const I18N = {                       // L395
  ro: { settings:"Setări", copy:"Copiază", … },
  en: { settings:"Settings", copy:"Copy",  … },
};
let UI = "ro";                       // L479
function t(k,a){                     // L480 — values may be functions
  const v = I18N[UI][k];
  return typeof v === "function" ? v(a) : v;
}
function applyUILang(){              // L588
  document.documentElement.lang = UI;
  document.querySelectorAll("[data-i]").forEach(el =>
    { el.textContent = t(el.getAttribute("data-i")); });
  …manual fixups…
}
```

Markup carries keys: `<button data-i="settings">Setări</button>`.
The literal text is the RO fallback if JS fails.

**Values can be functions** — use that for pluralisation and
interpolation rather than string concatenation:
```js
ro: { count: n => `${n} cuvinte` },
en: { count: n => `${n} word${n===1?'':'s'}` },
```

## Gap to close first: `data-i` only sets `textContent`

That's the whole reason `applyUILang` has a tail of manual fixups
(`ta.placeholder = …`, `b.textContent = …`, L593-596). With ~58 more
attribute strings across the other two apps, that tail doesn't scale.

**Extend the loop to handle attributes before porting anything:**

```js
function applyUILang(){
  document.documentElement.lang = UI;
  document.querySelectorAll("[data-i]").forEach(el =>
    { el.textContent = t(el.dataset.i); });
  const ATTRS = ["placeholder","title","aria-label","value","alt"];
  ATTRS.forEach(a => {
    const d = "data-i-" + a.replace("aria-label","aria");
    document.querySelectorAll(`[${d}]`).forEach(el =>
      el.setAttribute(a, t(el.getAttribute(d))));
  });
  …
}
```

Markup then reads:
```html
<input data-i-placeholder="searchHint">
<button data-i="save" data-i-title="saveTooltip">Salvează</button>
```

This removes nearly all manual fixups and is what makes porting to
`editor.html` (38 strings) tractable.

## ⚠ Do not conflate the two language axes in `index.html`

- `S.ui` / `UI` → **interface** language. Toggle `#uiLangBtn` (L599).
- `S.lang` → **spoken** language for dictation, `ro-RO`/`en-US`/auto
  (L921). Also has an "auto" value the UI language must never have.

They are independent: a user may want an English interface while
dictating Romanian. Never wire one to the other.

## Shared preference across pages

```js
const LANG_KEY = 'scula:ui-lang';   // 'ro' | 'en'
```

Use the storage wrapper at `index.html:510-531` (memory fallback when
`localStorage` throws). `index.html` currently persists `S.ui` inside
`caiet-vocal:settings` (L510) — on migration, keep writing that for
back-compat but read/write the shared key as the source of truth.

Set `<html lang>` on every switch — it drives hyphenation, spellcheck,
and screen-reader voice selection.

1. Extract strings → `I18N` object near the top of the app `<script>`.
   Start from these greps:
   ```bash

   grep -n "alert(\|confirm(\|prompt(" editor.html    # 5 here, 5 in markdown, 0 in index
   grep -n ">[A-Z][a-z].*<\/button>\|<label" editor.html
   ```
2. Add `data-i` / `data-i-*` attributes to markup.
3. Add `applyUILang()` + the language toggle to the **shared nav** so it
   appears in all three apps identically (nav is triplicated — see
   CLAUDE.md).
4. Run through the UI in both languages; check nothing overflows.

## Translation rules

- **Diacritics are mandatory:** ă â î ș ț. Use the proper comma-below
  characters `ș` (U+0219) / `ț` (U+021B), **not** the cedilla forms
  `ş`/`ţ` (U+015F/U+0163). They look nearly identical and break search.
  Verify: `grep -c $'\u015f\|\u0163' file.html` should be `0`.
- Romanian runs **~15-25% longer** than English. Toolbar buttons in
  `editor.html` are tight — check the mobile single-row toolbar
  (`@media (max-width:1180px)`) doesn't overflow after translating.
- Keep keys semantic (`saveTooltip`), not literal (`btn3`).
- One key per concept — don't reuse "Open" for a verb and a noun; RO
  needs different words.
- `LilitaOne-Regular.ttf` **does not cover Romanian diacritics** (upstream
  limitation). `fontCss()` in `editor.html` appends a `sans-serif`
  fallback so glyphs degrade instead of showing tofu. Don't use Lilita One
  for UI chrome — only Excalifont, Nunito, and Comic Shanns Mono are
  verified to cover ă â î ș ț.
